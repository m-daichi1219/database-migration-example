# PostgreSQL 用 Model Context Protocol (MCP) サーバーセットアップ手順

## 目的

このドキュメントでは、AI エディタ（Github Copilot など）がローカルまたはリモートの PostgreSQL データベースのスキーマ情報を取得し、読み取り専用の SQL クエリを実行できるようにするための MCP サーバー（`@modelcontextprotocol/server-postgres`）のセットアップ手順を説明します。

これにより、AI エディタはデータベースの構造を理解し、データに基づいたコード生成や分析支援を提供できるようになります。

## 前提条件

- **Node.js と npm (または yarn):** MCP サーバーを実行するために必要です。インストールされていない場合は、[Node.js 公式サイト](https://nodejs.org/)からダウンロードしてインストールしてください。
- **接続対象の PostgreSQL データベース:** AI エディタからアクセスしたい PostgreSQL データベースが稼働している必要があります。これはローカルマシン上、Docker コンテナ内、またはリモートサーバー上のいずれでも構いません。
  - データベースへの接続情報（ホスト名、ポート、データベース名、ユーザー名、パスワード）が必要です。
- **AI エディタ:** Github Copilot などの MCP サーバーに対応した AI エディタがインストールされていること。

## セットアップ手順

### 1. AI エディタの設定ファイルを開く

使用している AI エディタの設定ファイルを開きます。エディタによって設定方法が異なります。

- **Github Copilot の場合:**

  1. `Ctrl+Shift+P` (または `Cmd+Shift+P`) でコマンドパレットを開きます。
  2. `Open User Settings(JSON)` を検索して選択します。
  3. `settings.json` が開きます。

### 2. MCP サーバー設定の追加

設定ファイル内に、`mcp` (または同等の) セクションを見つけ、以下の設定を追加します。存在しない場合は作成します。

```json
{
  // ... 他の設定 ...

  "mcp": {
    // 他のMCPサーバー設定があればここに追加・維持

    "postgres-mcp-server": {
      // ← 任意の識別名 (例: "mypostgres", "project-db")
      "command": "npx",
      "args": [
        "-y", // npxがパッケージを一時的にダウンロードして実行することを許可
        "@modelcontextprotocol/server-postgres",
        // ↓ 接続するデータベースの接続文字列 (URI形式)
        "postgresql://<ユーザー名>:<パスワード>@<ホスト名>:<ポート>/<データベース名>"
      ]
    }
  }

  // ... 他の設定 ...
}
```

**接続文字列 `<...>` の部分を実際の環境に合わせて編集します:**

- `<ユーザー名>`: PostgreSQL に接続するユーザー名 (例: `postgres`, `app_user`)
- `<パスワード>`: 上記ユーザーのパスワード (例: `postgres`, `app_password`)
- `<ホスト名>`:
  - ローカルマシンで直接 PostgreSQL を実行している場合: `localhost`
  - **Docker コンテナ内で PostgreSQL を実行している場合:**
    - Docker Desktop (Mac/Windows) を使用: `host.docker.internal`
    - Linux 上の Docker: 通常は `localhost` または `127.0.0.1` (Docker ネットワーク設定による)
    - WSL2 上の Docker (ホストからアクセスする場合): `localhost` (WSL2 のネットワーク機能によりホストにポートフォワーディングされるため)
    - Docker Compose で同じネットワーク内に MCP サーバーを立てる場合: Docker Compose で定義したサービス名 (例: `db-primary`) ※この設定方法では通常コンテナ外から実行するため、上記いずれかのホスト名を使用します。
  - リモートサーバーの場合: そのサーバーのホスト名または IP アドレス
- `<ポート>`: PostgreSQL が待ち受けているポート番号 (デフォルト: `5432`)
- `<データベース名>`: 接続したいデータベース名 (例: `sampledb`)

**例:**

- ローカルのデフォルト設定の場合:
  `"postgresql://postgres:postgres@localhost:5432/sampledb"`
- Docker Desktop 上のコンテナの場合:
  `"postgresql://postgres:postgres@host.docker.internal:5432/sampledb"`

**注意:** パスワードに特殊文字が含まれる場合は、URL エンコードが必要になることがあります。

## トラブルシューティング

- **データベースが表示されない:**
  - 設定ファイル (`settings.json` など) の JSON 構文が正しいか確認してください。
  - 接続文字列が正しいか（ユーザー名、パスワード、ホスト名、ポート、DB 名）再確認してください。
  - PostgreSQL サーバーが起動しており、ネットワーク的に到達可能か確認してください。
- **認証エラー:** ユーザー名またはパスワードが間違っている可能性があります。
- **接続タイムアウト:** ホスト名またはポートが間違っているか、ネットワーク経路がない、またはファイアウォールでブロックされている可能性があります。
- **`npx` コマンドが見つからない:** Node.js/npm が正しくインストールされ、PATH が通っているか確認してください。

## セキュリティに関する注意

接続文字列に直接パスワードを記述するため、設定ファイルの取り扱いには注意してください。可能であれば、環境変数など、より安全な方法で認証情報を管理することを検討してください（ただし、MCP サーバーの設定方法が対応している必要があります）。
